## Findings

| Severity | Finding / evidence | Status or recommended action |
|---|---|---|
| High — availability | Nine photograph slots in Hero, Equipment and About used one deleted Supabase project's public object URLs. DNS lookup for the legacy host failed during the audit. | **Fixed:** all nine use repository-owned imports. Four original Git photos retained, five company-source replacements added. |
| High — functional | `src/components/sections/Contact.tsx`: form has no `action` or `onSubmit`; controls lack `name` attributes. Local browser submission with dummy data navigated to `/?` via GET with no body and cleared the fields. No message is sent. | **Open:** implement an authorized form backend and delivery/error states, or replace the misleading form with explicit email/phone contact. No external messages were sent. |
| High — dependency maintenance | Baseline `npm audit --json` reported 24 vulnerable packages: 16 high, 6 moderate, 2 low. Direct affected packages include Vite 5.4.8, React Router DOM 7.1.3 and PostCSS 8.4.47. | **Open:** controlled dependency upgrade and regression verification. Registry severity is not proof of exploitability in this static site; many router reports concern unused SSR/framework/server functionality. Vite reports concern development server exposure, not necessarily the static production files. |
| Medium — navigation | Footer quick links use `#services`, etc., on every route. Clicking Services on `/about` stayed on `/about#services`, with zero matching elements. | **Open:** route footer links to `/#…` and test cross-route navigation. |
| Medium — runtime robustness | `src/App.tsx` passes the URL hash straight to `document.querySelector`. Visiting `/#[` produced a DOMException in the browser. | **Open:** use validated fragment IDs and `getElementById`, with malformed-fragment handling. This is an uncaught error, not evidence of arbitrary script execution. |
| Medium — release/content verification | Footer asserts ISO 9001:2015/API Q1 certification and an HSE award; equipment specifications and staff roles are hardcoded without supporting records. | **Open:** obtain current company confirmation before a release. These claims were not established as false or independently verified. |
| Low — broken asset | `index.html` referenced nonexistent `/vite.svg`. | **Fixed:** uses bundled TRB logo; browser response 200. |
| Low — check reliability | Baseline lint failed on unused `Settings`; TypeScript failed on that and 11 unused React imports. Vite build alone did not catch these failures. | **Fixed:** remove only the unused imports. Run TypeScript and lint alongside build in CI. |
| Low — performance | Retained original hero is 1,924,598 bytes; equipment JPEGs are roughly 293–336 KB each. No responsive image variants. | **Open:** preserve originals and add optimized responsive derivatives in a later performance pass. New large About originals were downloaded as 1200-pixel JPEG renditions instead of shipping a 5.2 MB PNG. Equipment now lazy-loads and decodes asynchronously. |
| Low — maintainability | Both `ToolsSales.tsx` and `ToolsSales/index.tsx` exist; the app resolves the former, leaving the refactored directory unused. | **Open:** consolidate deliberately in a separate cleanup. |
| Low — accessibility | Mobile navigation toggle lacks `aria-expanded` and `aria-controls`. | **Open:** expose state and verify keyboard/focus behavior. No comprehensive accessibility audit performed. |
